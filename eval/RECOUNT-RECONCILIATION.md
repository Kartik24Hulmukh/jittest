## The "Published Numbers" in the Audit (D5 claim)

The D5 audit states: "Published (PR #122 / README): 18/30 bug rows executed,
4/18 proven_catch, 13/24 controls executed, 31/54 definitive."

These numbers (18/30, 4/18, 13/24, 31/54) do **not appear** in any file in
the current repository as of this audit:

- `docs/evidence/layer1b/REPORT.md` currently shows: 5 bug executed, 20 control executed,
  25 total definitive — matching this recount exactly.
- `README.md` Layer-1b section: not present. The README only covers the Layer-1 (83-row) cohort.
- `docs/evidence/layer1/REPORT.md`: describes the 83-row Layer-1 cohort (24/83 definitive),
  not the 54-row Layer-1b cohort.

The numbers 18/30, 4/18, 13/24, 31/54 appear to reference an **intermediate
state of PR #122** (the ENV-FIDELITY sweep PR) before its final amendment.
That intermediate state no longer exists in any file tracked by the current
branch.

## Disagreement Classification

The D5 audit identifies "four disagreements" between the audit's reference
numbers (from an intermediate PR #122 state) and the WO-19 recount:

| Metric | Audit reference | This recount | Difference |
| :--- | :--- | :--- | :--- |
| Bug rows executed | 18/30 | 5/30 | -13 |
| proven_catch (of executed bug) | 4/18 | 3/5 | different denominator |
| Control rows executed | 13/24 | 20/24 | +7 |
| Total definitive | 31/54 | 25/54 | -6 |

The movements go in opposite directions (bugs: fewer executed, controls: more
executed), which indicates this is a **definition change**, not a simple recount.

The intermediate PR #122 state likely used a different definition of "executed"
that included rows with `base_reproduction_failed` disposition as "attempted"
rather than "inconclusive". Under the current definition in recount.py
(`executed = verdict != "inconclusive"`), all `base_reproduction_failed` rows
have verdict `inconclusive` and are NOT counted as executed.

---

## Which Set Is Correct

The **current recount.py output (5 bug executed, 20 control executed, 25/54 definitive)
is the correct set** for the following reasons:

1. **Definition is explicit**: `executed = verdict != "inconclusive"` is now
   documented in recount.py code comments and in the JSON output's `definitions`
   block.

2. **Internally consistent**: recount.py's output matches `docs/evidence/layer1b/REPORT.md`
   exactly. The REPORT.md was published with signed receipts and was not disputed
   as fabricated.

3. **The audit's reference numbers are from an intermediate PR #122 state**
   that no longer exists in any tracked file. There is no signed evidence artifact
   or git-verified file in the current repository containing 18/30 or 31/54
   as published numbers.

4. **Honest accounting**: The base_reproduction_failed disposition (25 bug rows)
   means the test environment could not reproduce the passing baseline — these
   are genuine failures to execute and must be counted as inconclusive (loud
   refusal), not as "executed". Counting them as executed would be a fabrication.
