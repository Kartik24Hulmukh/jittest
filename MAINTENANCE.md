# Maintenance commitment

The closest prior project to this one, `qodo-ai/qodo-cover`, was archived with
this notice fifteen months after a very successful launch:

> `2025-06-15: This repository is no longer maintained. Please fork it if you
> wish to continue development or use it in your own projects.`

That abandonment is a large part of why this repository exists. It would be
absurd to repeat it, so the commitment is written down where it can be checked.

## What is promised

- **Issue triage within 7 days.** Labelled, or answered, or closed with a reason.
- **A release at least every 8 weeks** while the project is active, even if it
  is only dependency updates.
- **Security reports answered within 72 hours.** See `SECURITY.md`.
- **No silent abandonment.** If maintenance stops, the README gets a dated
  notice explaining why and naming a successor or a fork policy, within 30 days
  of the decision. Not fifteen months later.
- **The evaluation numbers stay current.** If a model change moves catch rate or
  false-positive rate, the README table is updated, including when the movement
  is unfavourable.

## What is not promised

- Support for languages beyond Python before there is a maintainer for them.
- A hosted service.
- Backwards compatibility on the `0.x` line, though breaking changes get a
  changelog entry and a migration note.
- Response times outside those above. This is currently maintained by one
  person.

## If you want to take it over

Open an issue titled "maintainership". A project that outlives its founder is
the goal, not a threat.
