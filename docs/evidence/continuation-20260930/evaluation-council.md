## Critical audit

### 1. The public 116-case template is not blinded or executable review material — Partial

Artifact-only counting confirms **116 cases = 80 population cases + 36 candidate-assertion cases**. All 116 are `not_started`; every template’s candidate-byte field is null. The committed custodian key resolves IDs to source/cohort pointers, so removing labels from the template does not blind it. Reusing those public IDs would permit unblinding. [^https://github.com/Kartik24Hulmukh/jittest/blob/6ca6698444718bdb58316d76f8c92ca9deccfacb/docs/evidence/ga73-reanalysis-20260930/README.md]

The inventory is useful: it includes nonreports and static exclusions, not just surfaced positives. But population truth and candidate assertion validity are different units. Reviewers need neutral revision-bound supported contracts and source context; a benchmark bug tag is not independently adjudicated contract validity, and a settled merge is not known-clean.

**Smallest remaining preparation:** a packet-completeness validator accepting only authorized retained originals whose byte hashes match telemetry. Leave missing cases indeterminate. Prepare fresh randomized IDs and a separate private mapping, lock two independent human phase-one reviews before exposing model/gold results, retain disagreements, then assess designated benchmark correspondence as a distinct second phase. Agent-generated judgments may prioritize acquisition, never populate independent-human labels.

The retained cost contract contains **zero events**, owner statement null, reconciled provider USD null and CI expense null. Click’s received credit observations (113 responses) and bug observations (78 responses) are historical subsets; generator invocation/retry totals cannot be reconstructed from them. [^https://github.com/Kartik24Hulmukh/jittest/blob/6ca6698444718bdb58316d76f8c92ca9deccfacb/docs/evidence/ga73-reanalysis-20260930/cost-reconciliation-contract.json]

At the inspected source, `HTTPLLM.complete` validates choices/content/usage and accounts tokens **before** adding `billing_cost`. A valid JSON response with documented billing but malformed completion content or usage raises first, discarding the charge observation. `_post` knows actual retry attempts but exports no event ledger. A request timeout’s debit is unknown, not zero. [^https://github.com/Kartik24Hulmukh/jittest/blob/6ca6698444718bdb58316d76f8c92ca9deccfacb/src/jittest/llm.py#L294-L358] [^https://github.com/Kartik24Hulmukh/jittest/blob/6ca6698444718bdb58316d76f8c92ca9deccfacb/src/jittest/llm.py#L360-L441]

**Implemented smallest correction:**

1. Capture successful-response billing immediately on returned body, before content/usage validation; preserve typed errors, existing token/call counters, retry/guard order and successful-response billing fields.
2. Add explicit opt-in caller-owned `dispatch_ledger` to HTTPLLM. Each actual `urlopen` attempt gets a fresh local dispatch ID, retry index and timestamp; each `complete` call gets its own local invocation ID. Cache hits, budget refusals and pre-dispatch failures have no dispatch ID. Real request IDs come only from recognized response ID headers; none are guessed from completion IDs. Credential-echo IDs are withheld.
3. Keep transport/body/content/usage status independent. Record parsed billing even on malformed content or billed HTTP errors; unknown/malformed/unreceived debit is null. Energy/noncredit observations are separate from credit debit. No URLs, payloads, prompts, response text, arbitrary headers, credentials or exception details enter the ledger.
4. Run/target/stage are supplied only by explicit caller context; otherwise null. This patch does not infer generator/assessor roles from prompts or wire them into unrelated callers. Caller-owned opt-in retention is not crash-durable or whole-system coverage.
5. Add an offline strict summary rejecting duplicate/missing dispatch IDs, fabricated nondispatch debits, nonfinite/negative amounts, invalid retry indices and inconsistent observed charges. It reports unknowns, missing metadata, unterminated dispatches and parse failures. **Wallet reconciliation remains false; total provider USD and CI expense remain null.**

This is a source-preparation increment, not paid-run cost evidence. Malformed charged responses may still not advance existing token/call-based budget accounting; retaining billing does not create a provider-side reservation or hard wallet ceiling. Other backends, CLI metadata/export wiring, crash durability and private invoice joins remain separate work.

## Premortem — five production failure modes

1. **JIT/identity races:** attempt inventory describes one pair but execution uses another checkout or mutable test bytes. Freeze resolved Git IDs/raw test hashes; bind independent receipt expectations; retain interruptions/refusals. Validate stale HEAD, wrong pair, dirty checkout and missing object controls. Existing engineering fixes do not eliminate deployment/event trust duties.
2. **Thread starvation:** request retries or queued work consume time while summary hides abandoned attempts. Real dispatch versus invocation distinction, timestamps and started/unknown events make this visible; bound host admission and record queue/cancellation clocks separately. This non-thread-safe client must not be advertised as a shared concurrent ledger implementation.
3. **Nondeterministic/runtime drift:** runner falls back or repeated assertion runs are not actually comparable. Preregister runner arm, record executable/version/probe/fallback and immutable runtime identity; retain all rerun outcomes. Collection/response coverage is not execution validity.
4. **False fiscal precision:** paid malformed/timeout responses vanish, duplicated invoice allocations appear cheap, or missing charges become zero. Observe billing before parsing; keep unknown null; reject duplicate dispatch/debit fiction; require independent sanitized statement joins and complete allocations for any reconciled total. Decimal observations are still not invoices.
5. **False semantic/product confidence:** public IDs unblind reviewers, benchmark correspondence is called field recall, or advisory green is treated as merge safety. Fresh private custody, locked independent labels, denominator-preserving default-Action measurement, explicit preview messaging and observed maintainer behavior—not council approval—are necessary controls.

Before implementation, freeze source and adverse fixtures; preserve failing evidence. Validate transport accounting using an owned localhost HTTP server: valid response, billed malformed content/usage, invalid JSON, HTTP402/410, retry503, timeout, actual connection refusal, cache/corrupt cache, budget refusal, pre-dispatch payload failure, metadata absence and credential-echo IDs. Fixtures are synthetic billing observations and never claimed provider invoices. Run dedicated unittest under system Python without pytest; run focused adjacent budget/transport/pipeline tests and Ruff. Retain failures and command-result hashes. Maximum five meaningful correction cycles/module; actual work here used three bounded source/test refinement rounds, without repetitive paid sweeps.

For the future census, require actual clean installed wheel/remote Action fixture acceptance, expected externally held signer/provenance/confinement, exact attempt partition reconciliation, interrupted/no-artifact rows and malformed receipt negatives. Docker-unavailable is an explicit unexecuted arm, not pass. Do not execute foreign corpus code to validate the instrumentation itself.
